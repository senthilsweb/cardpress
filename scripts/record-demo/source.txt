A bank statement is a PDF made for people, not for analysis. Turning a year of them into a cash-flow picture takes a pipeline, and the pipeline has four jobs.

First, ingest. Statements arrive as PDFs and exports from different banks, so each file is stored as it came, with its source and date, before anything touches it.

Second, parse. Every line becomes a row with a date, an amount, a description and a balance. Checks run here: the running balance has to add up, or the file is rejected instead of guessed at.

Third, categorise. Merchant names are cleaned up and mapped to categories such as payroll, rent, subscriptions and transfers. Rules handle the obvious ones, and a small model suggests the rest for a person to confirm.

Fourth, summarise. Monthly inflow, outflow, recurring payments and the lowest balance show up as a short cash-flow view. That is the part people actually read.

The lesson is the same at every step: keep the raw data, make each step checkable, and let a person approve what the machine suggests.
